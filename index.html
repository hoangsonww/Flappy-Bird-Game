What is in it

A small game, taken seriously

Everything below runs on the device with no account, no network and no setup. The backend adds a social layer on top — it never gates the game.

Six ways to play

One loop, six different arguments with it

Classic is the original tuning. The rest pull it in different directions — and Zen exists purely so you can practise a tricky gap without the run ending.

  • ✓Endless — difficulty climbs over 40 pipes, then plateaus so it stays fair.
  • ✓Time Attack — 60 seconds. Score, not survival.
  • ✓Hardcore — 118 pt gaps, heavier gravity, no power-ups.
  • ✓Daily — derived from the date, so everyone plays the identical layout.
Risk and reward

The safest line is rarely the interesting one

Every gap holds a coin. Collect it and your combo grows; skip one and it resets. The multiplier caps at ×8, which is enough to make a greedy run genuinely worth attempting.

  • ✓Five power-ups — shield, slow-motion, magnet, double points, shrink.
  • ✓Weather — wind, rain and fog, rolled from the run seed.
  • ✓Day → sunset → night → dawn, every 20 pipes.
  • ✓Your ghost flies beside you. Outrun it for the secret achievement.
Progress that sticks

Everything is counted, offline first

18 achievements worth 955 points, lifetime stats down to how you died, and eight bird skins bought with coins you actually earned. All of it unlocks with no account and no network.

  • ✓Monotonic sync — progress only moves forward, so replaying an old payload is a no-op.
  • ✓Medals at 10, 25, 50 and 100.
  • ✓Accessibility — reduce flashing, high contrast, VoiceOver, Reduce Motion.

Optional backend

Leaderboards, if you want them

A complete Node.js + TypeScript API with accounts, ranked boards, achievement sync and a daily challenge. One command starts it — the game finds it on its own, and shrugs when it is not there.

🤝 The handshake

  • The game probes the URL in Settings, then Info.plist, then localhost:4000.
  • It only accepts a server that answers protocol: "flappy-bird/1".
  • Discovery runs in the background — nothing ever blocks on it.
  • Offline runs queue locally and upload when a server appears.
Point it at the wrong port and it says so. Without the handshake, a stray service on :4000 would produce confusing failures three screens later instead of one clear message.

🛡 Fair play, described honestly

  • Impossible runs are rejected with 422.
  • Improbable runs are stored, flagged and kept off every board — evidence, not deletion.
  • Runs can be HMAC-signed with a shared secret.
  • That secret ships inside the app, so this raises the cost of casual scripting; it does not make a public leaderboard tamper-proof. The docs say exactly that.

How it is built

Decisions, written down

Three choices shaped everything else. Each has an architecture decision record explaining the trade-off, including what it costs.

🔌

The backend is optional

Requiring a server would make "install Docker" the first step of playing. Every online feature has an offline path, so the offline path never rots.

ADR 0001 →
🧩

The Xcode project is generated

project.pbxproj is derived from the file tree with deterministic IDs. Adding a file is touch + make xcodegen, and two branches never conflict.

ADR 0002 →
🗃

Two storage drivers, one suite

Postgres and in-memory behind the same contracts, with every test run against both. It has already caught a type-inference bug and a ranking difference.

ADR 0003 →
A concrete example. Running the suite against Postgres surfaced two bugs the in-memory driver hid: one query parameter bound to both an INTEGER and a BIGINT column — which Postgres refuses to type-infer, so every score submission returned 500 — and tied players receiving different ranks in SQL while sharing a rank in memory. Both would otherwise have shipped as "works on my machine".
Get started

Three commands, or one keystroke

You need Xcode. That is the whole dependency list for playing.

bash
git clone https://github.com/hoangsonww/Flappy-Bird-Game.git
cd Flappy-Bird-Game
open "Flappy Bird.xcodeproj"   # then ⌘R
bash
make doctor   # what you have, what it unlocks
make run      # build + launch in a simulator
make demo     # attract mode — it plays itself
make test     # 124 Swift unit tests
make test-ui  # 25 Swift UI tests
bash
make bootstrap  # hooks, dependencies, .env
make up         # Postgres + API in Docker
make seed       # demo players and runs
make ci         # the full local pipeline
